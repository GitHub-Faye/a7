# 任务16.3 - 实现Markdown验证功能

## 任务概述

**任务ID**: 16.3  
**任务标题**: 实现Markdown验证  
**任务描述**: 验证生成的Markdown是否符合marp-cli规范，并确保保持知识点层级结构。  
**任务依赖**: 任务16.2 (集成AI生成Markdown的功能)  

## 问题分析

当前系统的问题:
1. `validate_and_convert_markdown`方法直接调用marp-cli转换服务，没有事先验证Markdown内容
2. 如果生成的Markdown不符合marp-cli规范，可能导致转换失败
3. 没有验证Markdown是否正确表示了知识点的层级结构
4. AI生成Markdown时有简单的元数据检查和修复，但没有更全面的验证

## 技术方案

### 1. 创建独立的Markdown验证模块

在`marp_service`应用中创建一个新的`validation.py`模块，专门用于Markdown验证。该模块将包含以下功能:

- 验证marp前置元数据
- 验证幻灯片分隔符
- 验证标题层级结构
- 验证基本语法错误
- 自动修复常见问题

        self.errors = []

### 3. 实现验证功能

#### 3.1 前置元数据验证

验证Markdown是否包含必要的marp前置元数据:
- `marp: true`
- `theme: [主题名]`
- `paginate: true`(可选)

#### 3.2 幻灯片结构验证

- 验证是否有正确的幻灯片分隔符(`---`)
- 验证幻灯片数量是否合理(至少有标题页)
- 验证是否有空白幻灯片

#### 3.3 层级结构验证

- 验证标题层级是否正确(层级递增，不跳级)
- 验证知识点层级关系是否在Markdown中得到正确表示
- 验证每个知识点是否都有对应的内容

#### 3.4 语法验证

- 验证Markdown基本语法是否正确(标题、列表等)
- 验证是否有未闭合的代码块或引用
- 验证是否有明显的错误格式

## 实现注意事项

1. **渐进性验证**: 先验证基础结构，再验证细节
2. **宽容原则**: 对小问题发出警告但不阻止转换，只有严重问题才返回错误
3. **详细日志**: 记录所有验证问题和修复操作
4. **性能考虑**: 验证应该高效，不应显著增加处理时间
5. **可扩展性**: 设计应易于添加新的验证规则
